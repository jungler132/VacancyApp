# Vakano

Android-приложение (Expo SDK 57): лента вакансий с публичных площадок, каталог услуг, локальные оповещения. Гостевой режим работает без аккаунта; вход по почте включает синхронизацию.

- Пакет: `app.vakano.jobs`
- Схема: `vakano://`
- Поддержка: [worklysupport@proton.me](mailto:worklysupport@proton.me)
- Политика: [https://jungler132.github.io/VacancyApp/](https://jungler132.github.io/VacancyApp/)

AAB в этом репозитории **не собирается автоматически**. Сборка под Play — отдельный шаг, когда будет upload-keystore.

## Запуск

Нужны Node.js 20+, Yarn, Android SDK. Папки `node_modules/` и `android/` в git нет — они создаются локально.

```bash
yarn
yarn android
```

Тесты:

```bash
yarn test
```

Ключи — в `.env` (шаблон `.env.example`). Без Supabase приложение остаётся гостевым. Без ключей Adzuna / Jooble / USAJobs эти источники просто не включаются. Файл `.env.local` в git не попадает: туда кладут секреты сервера, приложение их не читает.

## Реклама (AdMob)

В AdMob создайте **два** блока для Android `app.vakano.jobs`:

1. **Межстраничное объявление** — имя например `vakano_interstitial`. Показ при открытии вакансии или чужой услуги: каждое 3-е открытие и не чаще раза в 90 секунд. Крестик рисует Google, не наш таймер на 3 секунды.
2. **Баннер** — имя например `vakano_feed_banner`. Низ ленты вакансий и услуг, над табами.

Остальные форматы (rewarded, native, app open) не подключайте.

В `.env` (потом `yarn android`, потому что App ID попадает в манифест):

```
EXPO_PUBLIC_ADMOB_ANDROID_APP_ID=ca-app-pub-…~…
EXPO_PUBLIC_ADMOB_INTERSTITIAL_ID=ca-app-pub-…/…
EXPO_PUBLIC_ADMOB_BANNER_ID=ca-app-pub-…/…
```

Пока переменных нет, в сборке тестовые ID Google.

**Сейчас тестовый режим включён** (`EXPO_PUBLIC_ADMOB_USE_TEST_ADS=1`): debug и локальный release показывают demo-объявления Google, боевые блоки `vakano_interstitial` / `vakano_feed_banner` не дергаются. Перед заливкой в Play поставьте `EXPO_PUBLIC_ADMOB_USE_TEST_ADS=0` и пересоберите.

Премиум без рекламы покупается через Google Play Billing (SKU `vakano_premium`). На debug sideload покупка не проходит — нужен продукт в Play Console и установка с внутренней тестовой дорожки.

В Play Console: «Да, в приложении есть реклама». Data safety: рекламный ID — да, обрабатывает Google. Покупки — да, обрабатывает Google Play.

## Google Play: что уже поправлено в коде

Чтобы первая публикация не упиралась в политику, в приложении сделано так:

1. **Премиум через Google Play Billing.** SKU `vakano_premium`. Кнопка больше не заглушка. На локальном debug покупка не сработает, пока нет внутренней тестовой дорожки.
2. **Реклама AdMob.** Пока `EXPO_PUBLIC_ADMOB_USE_TEST_ADS=1` — только demo-объявления Google. Официальные test ads можно кликать для проверки. Боевые блоки — нет.
3. **Debug-подпись.** Local release всё ещё debug-keystore — в Play такой AAB не заливать.

## Правила Play: что можно, что нельзя, что заполнить в Console

Ниже — сверка **текущего** приложения с типичными причинами отказа. Это не юрконсультация, но закрывает очевидные пункты.

### Можно (если честно описать в листинге)

| Тема | Как у нас | Что указать в Console |
| --- | --- | --- |
| Агрегатор вакансий | Запросы на **публичные API** площадок, которые пользователь включил | Не обещать «все вакансии HH» и не выдавать приложение за официальный клиент HeadHunter / Работа России / Adzuna |
| Гость + аккаунт | Офлайн на устройстве; после входа — Supabase | Data safety: аккаунт по желанию |
| Уведомления | Локальные, по фильтрам; фон через `expo-background-task` | Разрешение уведомлений; не заявлять фоновый GPS |
| Фото | Аватар и снимки услуги, сжатие на устройстве | Разрешение Photos только для этого |
| Жалобы | Есть репорт из приложения на почту поддержки | В анкете UGC: пользователи могут пожаловаться |
| 13+ | Не для детей | Анкета IARC / «не для детей»; не ставить Designed for Families |

### Нельзя / снимет модерация, если оставить как было

| Риск | Статус |
| --- | --- |
| Кнопка «Купить» без Play Billing, которая включает премиум | **Убрано.** Пока биллинга нет — премиум не продаём |
| Экран-заглушка, который выглядит как реклама | **Убран**, стоит живой AdMob |
| Политика пишет AdMob, а в APK рекламы нет | Политика совпадает с AdMob |
| AAB, подписанный **debug-keystore** | **Нельзя заливать в Play.** Если нет `keystore.properties`, Gradle ещё подпишет debug-ключом (sideload). Для Closed testing нужен `yarn aab` с upload-ключом |
| Скрапинг HTML площадок в обход ToS | В коде используются API, не парсинг страниц. HeadHunter без OAuth часто отвечает 403 — это не нарушение Play, но и не повод писать в сторе «полный HH» |
| Платежи картой / внешний магазин за цифровые фичи | Не делайте, пока нет Play Billing (или официальной программы alternative billing) |

### User-generated content (обязательная анкета)

Пользователи публикуют **свои вакансии Vakano** и **страницу услуг** (тексты, фото, телефон). Это UGC.

В Play Console нужно отметить:

- пользователи создают и видят контент других;
- есть механизм жалобы (он есть);
- контент не для детей;
- вы рассматриваете жалобы (почта поддержки).

Не обещайте модерацию «до публикации», если её нет: честнее «публикация сразу, жалобы вручную».

### Data safety (копировать в форму)

Пока **нет Play Billing** (реклама AdMob уже есть):

- **Приблизительное / точное местоположение:** не собираем. Город — это текст поиска, не GPS.
- **Рекламный ID:** да, обрабатывает Google AdMob.
- **Покупки в приложении:** да, разовый `vakano_premium` через Google Play Billing. Платежные данные обрабатывает Google, не Vakano.
- **Электронная почта / имя / телефон / фото:** да, **только если** пользователь вошёл и сам указал (аккаунт, услуга, вакансия Vakano). Назначение: функциональность приложения. Не продаём.
- **Сообщения / контент пользователя:** тексты вакансий и услуг, которые он публикует.
- **Идентификаторы аккаунта:** да, после входа (Supabase).
- **Передача третьим лицам:** поисковый запрос (текст, город, фильтры) уходит на включённые площадки вакансий; опционально фрагмент текста — в сервис перевода. Это нужно, чтобы лента работала.
- **Шифрование при передаче:** да (HTTPS).
- **Удаление аккаунта:** по запросу на `worklysupport@proton.me` (как в политике).

После Play Billing: отметить покупки. Политику GitHub Pages задеплойте из `docs/`.

## Подпись (AAB для Play)

Плагин `plugins/withAndroidReleaseSigning.js` читает `keystore.properties` в корне. Если файла нет — release остаётся на debug (только sideload). Если есть — AAB подписывается upload-ключом.

Один раз на машине разработчика:

```bash
node scripts/make-upload-keystore.cjs
```

Потом:

```bash
yarn aab
```

Готовый файл: `dist/Vakano.aab` → Play Console → **Closed testing** → Create new release.

Не коммитьте `upload-keystore.jks` и `keystore.properties`. Потерять ключ = нельзя обновлять приложение. Храните копию `.jks` и пароль вне репозитория (менеджер паролей + флешка).
